# 격리·트리아지 리허설 기록표

| 항목 | 내용 |
|---|---|
| 대본 | `docs/isolation_demo_script.md` |
| 작성 | 배기윤 (시나리오) |
| 진행 조건 | 격리 API(PR #35)·확인 페이지(PR #39)가 main에 있음 → **지금 바로 가능**. 서버는 `LIVE_CAPTURE_ENABLED=1 ISOLATION_ENABLED=1`로 켬 |

**리허설 1회 = 대본 장면 1~9를 처음부터 끝까지.** 매번 DB를 비우고 시작합니다(`최신main_테스트_명령어.md` 1단계). 기록표에 웹훅 주소·토큰·비밀번호를 적지 않습니다. 오류 문장에 들어 있으면 `[가림]`으로 바꿉니다.

## 1. 통과 기준 (제안 — PM 확정 필요)

아래 7개를 **모두** 만족해야 그 회차가 통과입니다.

| # | 기준 | 어떻게 확인 | 관련 장면 |
|---|---|---|---|
| P1 | 링크를 **열기만** 했을 때는 격리되지 않는다 | 확인 페이지만 연 상태에서 ping 성공 | 5 |
| P2 | 「승인」 뒤 attacker가 끊긴다 | ping·curl 모두 실패. 승인 후 걸린 시간을 기록(기준 시간은 PM이 정함) | 5·6 |
| P3 | 「해제」 뒤 복구된다 | ping 성공 + IP가 `172.28.0.100` | 7·8 |
| P4 | 같은 링크로 다시 승인하면 거절된다 | 같은 링크를 다시 열고 승인 → 「Token already used」 | 7 이후 |
| P5 | FP로 저장하면 기본 목록에서 사라지고, 토글로 돌아온다 | 화면 | 4-a |
| P6 | TP 저장(판정·메모·담당자·조치)이 새로고침 후에도 남는다 | 화면(F5) | 4-b·9 |
| P7 | 시연이 끝난 뒤 실습망이 정상이다 | (attacker_터미널.4, `.venv` 불필요) `cd ~/RookiRooki/scenarios/lab && docker compose ps` → 3개 모두 `Up` | 끝 |

- **합격 조건 (제안):** 3회 **연속** 통과. 한 번이라도 실패하면 원인을 적고 **처음부터 다시 3회**를 셉니다.
- 성공한 회차의 화면을 **녹화**해 두면, 발표 중 실패했을 때 대체 시연(A단계)에서 보여 줄 수 있습니다(제안).

## 2. 1회차에 꼭 같이 확인할 것 (아직 실시간으로 확인하지 못한 것)

| 항목 | 기대 (근거) | 실제 |
|---|---|---|
| 장면 1 경보 건수 | 7건: SEV1 3 · SEV2 2 · SEV3 2 (`c2_ssrf.pcap` 오프라인 실측) | |
| 장면 1 스크립트 시간 | 약 35~45초 (녹화본 첫~마지막 경보 약 36초) | |
| 장면 3 검색어 한 건 | SID 1000001 · HTTP 200 · SEV1 경보 1건 (오프라인 확인 완료) | |
| 장면 1~3 뒤 Discord 「격리 확인」 링크 개수 | 4개: SQLi·XSS·SSRF 성공·장면 3 오탐 (SEV1만 링크, `backend/isolation.py:14`) | |
| 장면 1 끝 → 장면 5 승인까지 걸린 시간 | 10분 안 (토큰 유효시간, `backend/isolation.py:15`) | |
