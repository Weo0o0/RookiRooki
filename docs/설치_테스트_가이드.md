## 1. 사전 준비 (최초 1회)

### 1-1. Windows에서 WSL2 Ubuntu 확인 및 진입 (서버_터미널.1)

`PowerShell_터미널.0`은 `wsl -l -v`, `wsl --set-version` 같은 Windows 쪽 명령을 실행하는 창입니다. Ubuntu 창과 구분해서 쓰세요.

`(PowerShell_터미널.0)` — `.venv 불필요`
```powershell
wsl -l -v
```
- `Ubuntu`의 `VERSION`이 **2**인지 확인합니다.
- 1이면 `wsl --set-version Ubuntu 2`로 올립니다.
- Ubuntu가 없으면 `wsl --install -d Ubuntu`로 설치합니다.
- **Docker Desktop을 쓰고 있다면 종료**해 두는 것을 권장합니다(WSL2 Ubuntu 내부 Docker Engine과 충돌할 수 있습니다).

Linux 명령을 실행하기 전에는 항상 PowerShell에서 Ubuntu로 먼저 들어갑니다. `서버_터미널.1`은 첫 Ubuntu 창으로, 패키지 확인·클론·`.venv`·`pytest`를 거쳐 5단계에서 `uvicorn`을 계속 실행하고 11단계 DB 초기화에도 다시 쓰므로 닫지 마세요.

**새 창 진입 순서 (서버_터미널.1)**: ① PowerShell 새 창을 엽니다 → ② 아래 `wsl -d Ubuntu` → ③ 아래 `cd ~/RookiRooki`

`(서버_터미널.1)` — `PowerShell 새 창에서 입력 · .venv 불필요`
```powershell
wsl -d Ubuntu
```

`(서버_터미널.1)` — `Ubuntu 진입 후 입력 · .venv 불필요`
```bash
cd ~/RookiRooki
```

**성공하면 이렇게 보여요**: 프롬프트가 `PS C:\...>`에서 `사용자@호스트:~$` 형태로 바뀝니다. (저장소를 클론하기 전인 처음에는 `cd ~/RookiRooki`가 `No such file or directory`로 실패하는 것이 정상이며, 2단계에서 클론한 뒤부터 사용합니다.)

### 1-2. 필수 패키지 확인 (Python, git, Suricata, jq)

`(서버_터미널.1)` — `.venv 불필요`

설치되어 있지 않다면 아래 명령으로 설치합니다.

> **중요 (Suricata 설정 파일 권한)**: 백엔드는 PCAP 업로드 시 `sudo` 없이 `suricata -r ...`을 실행합니다. Ubuntu PPA로 설치하면 `/etc/suricata/suricata.yaml` 읽기 권한이 `root` 전용일 수 있으므로 권한을 확인하고 필요 시 읽기 권한을 열어 둡니다.

`(서버_터미널.1)` — `.venv 불필요`

- `python3 --version`: `Python 3.10` 이상 (또는 `3.12`/`3.13`)
- `suricata -V`: `This is Suricata version 8.0.8 RELEASE` (팀 표준 PC 기준)
- `ls -l /etc/suricata/suricata.yaml`: `-rw-r--r--`로 일반 사용자 읽기 가능

> **Docker Engine(선택 10단계용)**: 실습망 컨테이너를 직접 띄울 분만 `scenarios/lab/WSL2_Docker_환경구축_종합명령어.md`의 1~3단계(`/etc/wsl.conf` `systemd=true` 설정 후 Docker Engine 설치)를 함께 진행하세요. 이미 저장소에 녹화된 PCAP 파일이 있으므로 Docker 없이도 1~9단계 테스트는 모두 가능합니다.

> **macOS 참고**: Docker Desktop 환경에서는 호스트에서 `br-minisiem` 브리지를 직접 tcpdump로 잡기 어렵습니다. 실습망 녹화가 필요할 때는 `docker-compose.yml`의 `desktop-capture` 프로필을 쓰거나, 저장소에 포함된 `scenarios/lab/pcaps/` 파일로 1~9단계만 테스트하세요.

## 5. 백엔드 실행 (`:8000`)

백엔드 진입점은 `backend/main.py`의 `app`입니다. 실행 전에 필요 시 깨끗한 상태로 시작하려면 기존 DB를 지우고 실행할 수 있습니다.

`(서버_터미널.1)` — `.venv 활성화 필요`

**성공하면 이렇게 보여요**:
- 터미널에 `Uvicorn running on http://127.0.0.1:8000` 로그가 출력되고 대기 상태가 됩니다(`서버_터미널.1` 창은 켜 둡니다. 닫으면 백엔드가 종료됩니다).
- 브라우저에서 `http://localhost:8000/docs`를 열면 FastAPI Swagger 문서(`/api/pcap/upload`, `/api/ingest/sample`, `/api/alerts`, `/api/alerts/{id}`, `/api/alerts/{id}/triage`, `/api/stats`)가 보입니다.

## 6. 프론트엔드 열기 (`:5500`) 및 Mock / Live 전환 (프론트_터미널.2)

새 PowerShell 창을 열고 Ubuntu로 들어간 뒤 프론트엔드 서버를 켭니다. `프론트_터미널.2`는 `http.server`를 계속 실행하는 창이므로 닫지 마세요.

**새 창 진입 순서 (프론트_터미널.2)**: ① PowerShell 새 창을 엽니다 → ② 아래 `wsl -d Ubuntu` → ③ 아래 `cd ~/RookiRooki`

```powershell
wsl -d Ubuntu
```

`(프론트_터미널.2)` — `Ubuntu 진입 후 입력 · .venv 불필요`

   - 아직 데이터를 넣지 않았다면 전체 경보 `0`으로 빈 목록이 표시되는 것이 정상입니다.

## 8. PCAP 업로드 테스트 (`POST /api/pcap/upload`)

저장소 `scenarios/lab/pcaps/`에는 4개의 PCAP 파일이 준비되어 있습니다. 백엔드는 업로드 시 `suricata -r <파일> -S rules/custom.rules -l <출력폴더> -k none --runmode single`을 실행합니다.

### 방법 A: 대시보드 웹 화면에서 업로드
1. `http://localhost:5500`에서 **Live API** 모드를 선택합니다.
2. 상단 **📁 PCAP 업로드** 버튼을 눌러 `~/RookiRooki/scenarios/lab/pcaps/` 아래 `.pcap` 파일을 선택합니다(폼 필드명 `file`, 최대 20MB, `.pcap`/`.pcapng` 지원).
3. 상태 배너에 `✅ '<파일명>' 분석 완료! 경보를 갱신합니다.`가 뜨고 목록이 갱신됩니다.

### 방법 B: `curl`로 직접 업로드 테스트
샘플 12건과 섞이지 않게 PCAP별 단독 결과를 보려면 먼저 DB를 비우고(11단계 참고) 업로드하세요.

`(요청_터미널.3)` — `.venv 불필요`
```bash
cd ~/RookiRooki
curl -sS -X POST http://localhost:8000/api/pcap/upload -F "file=@scenarios/lab/pcaps/lab_capture.pcap" | python3 -m json.tool
```

`c2_ssrf.pcap` 테스트(새 DB에서 업로드 권장):

`(요청_터미널.3)` — `.venv 불필요`
```bash
cd ~/RookiRooki
curl -sS -X POST http://localhost:8000/api/pcap/upload -F "file=@scenarios/lab/pcaps/c2_ssrf.pcap" | python3 -m json.tool
```

**PCAP별 기대 결과 (빈 DB 기준)**:

## 12. 자주 나는 문제 해결

| 증상 / 오류 | 원인 | 해결 방법 |
|---|---|---|
| `Address already in use` (`:8000` 또는 `:5500`) | 이전 서버 프로세스가 아직 살아 있음 | `ss -tlnp \| grep -E ':8000\|:5500'`으로 PID 확인 후 `kill <PID>` (또는 `pkill -f "uvicorn backend.main:app"`) |
| 웹에서 Live API 전환 시 `API 연결 실패` / 브라우저 콘솔 CORS 오류 | `frontend/index.html`을 `file://`로 열었거나 허용 Origin 불일치 (`backend/main.py` 기본값: `http://localhost:5500,http://127.0.0.1:5500`) | 반드시 `(프론트_터미널.2)`에서 `python3 -m http.server 5500` 실행 후 `http://localhost:5500`으로 접속 |
| PCAP 업로드 시 `HTTP 503 - Suricata unavailable` | WSL2 Ubuntu에 `suricata` 미설치 | 1-2단계 대로 `suricata` 설치 후 `suricata -V` 확인 |
| PCAP 업로드 시 `HTTP 502 - Suricata failed with return code ...` | `/etc/suricata/suricata.yaml` 권한 부족(`Permission denied`) 또는 룰 파일 오류 | `sudo chmod 644 /etc/suricata/suricata.yaml` 적용. `suricata -T -S rules/custom.rules`로 룰 문법 확인 |
| 같은 PCAP을 올렸는데 `alerts_stored: 0` | `backend/main.py`의 SHA-256 중복 업로드 방지(`pcap_uploads`) 동작 | 의도된 동작(`duplicate_of` 확인). 재테스트하려면 11단계 대로 `backend/data/alerts.db` 삭제 후 재실행 |
| `Cannot connect to the Docker daemon` / `permission denied ... docker.sock` | systemd 미활성화, Docker 서비스 중지, 또는 `docker` 그룹 미적용 | `/etc/wsl.conf`에 `systemd=true` 설정 후 `wsl --shutdown`, `sudo usermod -aG docker $USER` 후 Ubuntu 창 재시작 |
| `tcpdump: br-minisiem: No such device` | Docker 실습망이 켜지지 않음 | `cd ~/RookiRooki/scenarios/lab && docker compose up -d --build` 먼저 실행 |
| Windows 경로(`/mnt/c/...`)에서 `pytest`/업로드가 느리거나 권한 오류 | WSL2에서 Windows 파일시스템 접근 시 느리고 권한 메타데이터 충돌 | 저장소를 반드시 Ubuntu 홈(`~/RookiRooki`)에 클론해 작업 |
| (격리 기능을 켠 경우) 격리 API가 `Docker permission denied`(503)를 돌려줌 | 사용자 계정이 `docker` 그룹이 아님 | 위 `docker.sock` 행과 같은 조치(`docker` 그룹 적용 후 Ubuntu 창 재시작) |

> **주의**: `docker` 그룹은 사실상 root 권한이므로 실습 PC에서만 사용합니다.

## 13. 알려진 제한 사항 (현재 `main` 기준)

1. **Live API 모드 분석 명령어 패널 숨김**: 프론트엔드·백엔드 분석 패널 기능은 구현되어 있으나, 현재 공식 `scenarios/playbooks.json`에 아직 `analysis` 필드가 들어가 있지 않아 Live 모드에서는 분석 명령어 패널이 숨겨집니다(시나리오 담당 PR 머지 후 Live에서도 6종 모두 표시 예정). Mock 모드에서는 6종 모두 확인할 수 있습니다.
2. **경보 목록에 같은 공격이 두 줄씩 표시됨**: 공식 `scenarios/sample_eve.json`이 공격 6종당 서로 다른 이벤트 2건씩(총 12건)으로 구성되어 있어 정상 동작입니다.
3. **웹 화면 실시간 알림 팝업 미구현**: 현재 버전에는 브라우저 토스트/알림 팝업 UI가 아직 없으며 프론트엔드 후속 작업으로 추가될 예정입니다.
