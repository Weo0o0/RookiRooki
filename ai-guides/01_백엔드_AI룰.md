## 고정 규칙 (6종 표) — 철자와 SID를 바꾸지 말 것
- sqli 1000001. 기본 SEV3. 해당 요청 HTTP 200이면 SEV1. MITRE T1190.
- xss 1000002. 기본 SEV3. 해당 요청 HTTP 200이면 SEV1. MITRE T1189.
- bruteforce 1000003. SSH 22 연결 횟수 threshold. 기본 SEV2. 격상 없음. MITRE T1110.001.
- portscan 1000004. 룰은 ![22,80] 유지. 샘플·pcap 목적지 포트로 22, 80 금지(2026-11-24 PM 결정 A안). 기본 SEV3. 격상 없음. MITRE T1046.
- c2_beacon 1000005. 반복 연결 횟수 threshold. 격상 없음. MITRE 가안 T1071.001, 기본 심각도 가안 SEV2.
- ssrf 1000006. HTTP 200이면 sqli/xss처럼 SEV1 격상. MITRE 가안 T1190. 기본 심각도는 아직 없음.
카테고리 키 철자는 정확히 c2_beacon, ssrf 입니다(하이픈·대문자 금지).

## 백엔드 계약 (바꾸지 말 것)
- GET /api/alerts : 쿼리 severity=SEV1|SEV2|SEV3|SEV4, limit 1–200(기본 50), offset≥0. 응답 {items,total,limit,offset}. 정렬 id DESC.
- GET /api/alerts/{id} : 없으면 404, 메시지 "Alert not found".
- 경보 19개 키: id, timestamp, sid, category, signature, mitre_id, src_ip, dest_ip, dest_port, http_status, severity, is_confirmed_risk, pii_masked, raw_url, verdict, observation, assessment, confidence, playbook.
- PATCH /api/alerts/{id}/triage : verdict=TP|FP|UNREVIEWED, confidence=HIGH|MEDIUM|LOW, observation/assessment 각 2000자. 빈 {}는 422, 메시지 "At least one field is required for triage update". password= 와 token= 값은 [MASKED].
- POST /api/pcap/upload : form 필드 이름 file. sha256 중복 시 200, alerts_stored=0, duplicates_skipped=N, duplicate_of=이전 upload_id(새 upload_id는 발급).
- POST /api/ingest/sample : scenarios/sample_eve.json 을 읽고 {alerts_stored,duplicates_skipped,skipped_lines} 반환.
- GET /api/stats : {total,severity_counts,category_counts,mitre_coverage,blind_rules}.
- playbook 구조는 시나리오 파일 기준: name, actions.linux / actions.ufw 의 verify·block·rollback, preserve_evidence_first. 백엔드는 카테고리 키로 찾아 그대로 붙입니다. 프론트가 읽는 구조와 맞추되, 프론트 파일은 고치지 마세요.
- 파서는 event_type=alert 이고 signature_id 가 CATEGORIES 에 있는 행만 저장합니다. 지금 코드(eve_parser.py:4, :67)는 1000001–1000004만 있습니다. 1000005·1000006을 넣지 않으면 새 샘플은 버려집니다.
- http_status 와 200→SEV1 격상(eve_parser.py:89, :94)은 지금 sqli, xss만입니다. ssrf를 포함하세요. c2_beacon은 포함하지 마세요.
- 가안 MITRE·심각도를 코드에 넣을 수는 있습니다. 확정으로 단정하지 마세요.
