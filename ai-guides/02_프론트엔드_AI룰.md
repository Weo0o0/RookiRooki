# 프론트엔드 담당 AI 룰

> 사용법: 아래 「AI 룰」 전체를 AI 대화창 맨 앞에 붙여 넣고, 그 다음에 질문과 `frontend/index.html` 내용(또는 화면·콘솔 오류)을 붙여 넣으세요.
> 기준: 최신 main `0a70475` (PR #10 머지 후, 프론트는 PR #9이 이미 포함됨). 고칠 파일은 `frontend/index.html` 하나입니다.

## 꼭 기억할 5가지
1. Live 목록은 `data.items`를 읽어야 합니다. 지금은 `:379`가 `data.alerts`를 읽어 목록이 비어 있습니다.
2. 플레이북은 `actions.linux` / `actions.ufw` 아래의 verify·block·rollback을 읽어야 합니다. 지금은 `:564-568`이 `pb.block`만 봐서, 실제 데이터에서는 명령어가 안 나옵니다.
3. 모드를 바꾸거나 목록이 비면 이전에 열어 둔 상세를 비워야 합니다.
4. 필터·차트·Mock에 6종(`sqli`, `xss`, `bruteforce`, `portscan`, `c2_beacon`, `ssrf`)을 넣으세요. Mock 출발지는 `172.28.0.100`, XSS MITRE는 `T1189`입니다.
5. 화면에 넣는 문자열은 `textContent` 또는 `escapeHtml()`만 쓰세요. 차단 명령어는 복사만 되고, 실행 버튼은 없습니다.

머지 순서에서 프론트 PR은 **백엔드 다음**입니다. Live 버그 3개와 6종 UI는 같은 `index.html`이므로 한 브랜치·한 PR로 묶는 것을 권장합니다. `main`에 직접 푸시하지 마세요.

화면 속 경보 건수(샘플이 늘어난 뒤)는 아직 확정 전이면 지어내지 마세요.

## 셀프 테스트 명령어

Windows에서 Ubuntu를 연 다음, 터미널을 나눠 쓰세요.

(PowerShell) — `.venv` 불필요
```powershell
wsl -d Ubuntu
```

(서버) — `.venv` 활성화 필요
```bash
cd ~/RookiRooki
git checkout main
git pull origin main
# 기능 브랜치에서 작업하세요. 예: git checkout -b fix/frontend-live-and-six
source .venv/bin/activate
rm -f backend/data/alerts.db
uvicorn backend.main:app --port 8000
```

(요청) — `.venv` 불필요. 백엔드가 살아 있는지 확인합니다.
```bash
curl -sS -X POST http://127.0.0.1:8000/api/ingest/sample | python3 -m json.tool
curl -sS "http://127.0.0.1:8000/api/alerts?limit=50" | python3 -c "import sys,json;d=json.load(sys.stdin);print('keys',list(d), 'n',len(d.get('items') or []))"
```

(프론트) — `.venv` 불필요
```bash
cd ~/RookiRooki/frontend
python3 -m http.server 5500
```

브라우저에서 `http://localhost:5500`을 엽니다.
