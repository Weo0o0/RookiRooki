# 시나리오 담당 AI 룰

> 사용법: 아래 「AI 룰」 전체를 AI 대화창 맨 앞에 붙여 넣고, 그 다음에 질문과 파일 내용(또는 오류 로그)을 붙여 넣으세요.
> 기준: 최신 main `0a70475` (PR #10 머지 후). 담당 파일은 `scenarios/sample_eve.json`, `scenarios/playbooks.json`, `scenarios/lab/*`, `docs/playbooks_guide.md`, `docs/sample_eve_guide.md` 입니다.

## 꼭 기억할 5가지
1. 공격과 녹화는 Docker 실습망 `172.28.0.0/24` 안에서만, 녹화는 Docker 브리지(`br-minisiem`)에서만 합니다. C2와 SSRF 대상도 이 망 밖으로 나가면 안 됩니다.
2. portscan 목적지 포트로 **22, 80은 쓰지 않습니다.** 룰이 `![22,80]`으로 제외합니다. 지금 `sample_eve.json` 14번째 줄은 아직 `dest_port` 80입니다. **이 한 줄을 8080으로 고치는 선행 PR을 먼저** 올립니다.
3. 카테고리 키는 `sqli`, `xss`, `bruteforce`, `portscan`, `c2_beacon`, `ssrf`입니다. 철자를 바꾸지 마세요.
4. `sample_eve.json`은 BOM 없는 UTF-8 + LF, 한 줄에 JSON 하나(NDJSON)입니다. `playbooks.json`은 배열이 아니라 객체입니다.
5. C2는 attacker 172.28.0.100에서 victim-web 172.28.0.10:8443/tcp로 가며, 같은 출발지가 30초 안에 5회 연결하면 경보 1회입니다. SSRF 경로는 victim-web:80 GET /fetch?url=<내부 주소>입니다. 공식 샘플 경보는 12건(SEV1 3 / SEV2 4 / SEV3 5)이며, pcap(c2_ssrf.pcap)에 룰을 적용하면 7건입니다. 그 외 아직 비어 있는 값(테스트 개수, SSRF 404 동작)은 지어내지 마세요.

## 시나리오 계약
1) scenarios/sample_eve.json
- NDJSON, 한 줄에 JSON 하나, 배열로 감싸지 말 것. UTF-8 BOM 없음, LF(CRLF 금지).
- 공식 샘플 경보는 12건(SEV1 3 / SEV2 4 / SEV3 5)입니다. 줄 수와 짝 구조는 시나리오 샘플 파일을 따르세요. (PR #13 머지 전의 main은 16줄, alert 8개(유형당 2) + 짝이 되는 http/flow일 수 있습니다.)
- 웹(sqli/xss/ssrf)은 같은 요청의 alert와 http를 짝으로 둡니다. flow_id를 맞추고, 요청이 여러 개이면 tx_id 또는 URL도 같아야 격상이 정확합니다.
- HTTP 200 격상 사례와 200이 아닌 사례, 마스킹 시험용 가짜 password= 또는 token= 를 둡니다. 실제 비밀번호는 넣지 마세요.
- 백엔드가 경보로 저장하는 SID는 파서 CATEGORIES에 있는 것만입니다. 백엔드 PR 전에는 1000005·1000006 샘플이 저장되지 않을 수 있습니다. 그 경우 파서 미반영을 함께 적으세요.
- 공식 샘플(PR #13 기준) 적재 결과는 alert 12건(SEV1 3 / SEV2 4 / SEV3 5), skipped_lines 0 입니다. pcap(c2_ssrf.pcap)에 룰을 적용하면 7건입니다.

2) scenarios/playbooks.json
- 최상위는 객체. 최종 키: sqli, xss, bruteforce, portscan, c2_beacon, ssrf.
- 배열이면 백엔드가 playbook을 모두 null로 돌립니다.
- 각 항목: name, actions.linux.{verify,block,rollback}, actions.ufw.{verify,block,rollback}, preserve_evidence_first. 주소·포트는 {{SRC_IP}}, {{DEST_IP}}, {{DEST_PORT}}만.

3) 실습 앱·트래픽·pcap
- 지금 victim-web/app.py 에는 /, /health, /login, /search 만 있습니다. SSRF 경로는 GET /fetch?url=<내부 주소>이며, 성공 200·실패 4xx를 나눌 수 있어야 합니다.
- lab-traffic.sh 는 지금 4종만 보냅니다. 새 트래픽도 실습망 안에서만.
- attacker 컨테이너는 기본적으로 sleep 중이며, C2는 공격자가 victim-web 172.28.0.10:8443/tcp로 트래픽을 보내는 구조를 유지합니다. 다른 포트는 지어내지 마세요.
