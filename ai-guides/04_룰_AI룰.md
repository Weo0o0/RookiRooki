# 룰 담당 AI 룰

> 사용법: 아래 「AI 룰」 전체를 AI 대화창 맨 앞에 붙여 넣고, 그 다음에 질문과 `rules/custom.rules`, `rules/rule_catalog.json` 내용(또는 eve.json 로그)을 붙여 넣으세요.
> 기준: 최신 main `0a70475` (PR #10, sqli rev2 포함). 담당 파일은 `rules/custom.rules`, `rules/rule_catalog.json` 뿐입니다.

## 꼭 기억할 5가지
1. 새로 넣을 SID는 `c2_beacon` 1000005, `ssrf` 1000006입니다. 기존 1000001–1000004의 의미와 `portscan`의 `![22,80]`은 바꾸지 마세요.
2. C2는 반복 연결 횟수 threshold, SSRF는 HTTP 200이면 SEV1 격상(격상 계산은 백엔드)입니다.
3. C2는 attacker 172.28.0.100에서 victim-web 172.28.0.10:8443/tcp로 가며, 같은 출발지가 30초 안에 5회 연결하면 경보 1회입니다. SSRF URI는 GET /fetch?url=<내부 주소>입니다. 이 확정값으로 룰을 맞추고, 그 외 숫자는 지어내지 마세요.
4. C2·SSRF 모두 실습망 `172.28.0.0/24` 안에서만 탐지되도록 쓰세요.
5. MITRE는 가안입니다. c2_beacon `T1071.001`, ssrf `T1190`. 확정이라고 단정하지 마세요.

## 셀프 테스트 명령어

Windows에서 Ubuntu를 연 다음, 터미널을 나눠 쓰세요.


카탈로그·SID 확인 (요청) — `.venv` 불필요
```bash
cd ~/RookiRooki
git checkout main
git pull origin main
# 기능 브랜치에서 작업하세요.

python3 -c "
import json
from pathlib import Path
rules=json.loads(Path('rules/rule_catalog.json').read_text())
for r in rules:
    print(r.get('sid'), r.get('category'), r.get('mitre_id'), r.get('data_sources'))
"
# portscan 제외 포트가 그대로인지 확인. ![22,80] 이 보여야 합니다.
grep -n 'sid:1000004\|!\[22,80\]' rules/custom.rules
```

공식 pcap으로 기존 4종 확인 (요청) — `.venv` 불필요. Suricata가 설치된 PC에서만.
```bash
mkdir -p /tmp/suricata_out
# 기존 카탈로그 주의사항: threshold 검증은 --runmode single 을 씁니다.
suricata -r scenarios/lab/pcaps/lab_capture.pcap -S rules/custom.rules -l /tmp/suricata_out -k none --runmode single
python3 -c "
import json
from pathlib import Path
from collections import Counter
c=Counter()
for line in Path('/tmp/suricata_out/eve.json').read_text().splitlines():
    if not line.strip():
        continue
    o=json.loads(line)
    if o.get('event_type')=='alert':
        c[(o.get('alert') or {}).get('signature_id')]+=1
print(dict(c))
"
```

- 지금 `lab_capture.pcap`은 PR #10 기준 4종(1000001–1000004) 각 1건이 정상입니다.
- pcap(c2_ssrf.pcap)에 룰을 적용하면 7건입니다. lab_capture.pcap의 4종 각 1건(PR #10)과 섞지 마세요.

업로드 경로로 확인하려면 백엔드를 띄운 뒤 `POST /api/pcap/upload`를 씁니다. 필드 이름은 `file`입니다. 백엔드 파서가 아직 새 SID를 모르면 룰이 탐지해도 저장되지 않을 수 있습니다.

```text
## 고정 규칙 (6종 표) — 철자와 SID를 바꾸지 말 것
- sqli 1000001. HTTP URI. 기본 SEV3, 200이면 백엔드가 SEV1. MITRE T1190. 현재 rev 2. 임의로 되돌리지 말 것.
- xss 1000002. HTTP URI. 기본 SEV3, 200이면 SEV1. MITRE T1189.
- bruteforce 1000003. 172.28.0.11 22, threshold type both, track by_src, count 4, seconds 60. 격상 없음. MITRE T1110.001.
- portscan 1000004. $HOME_NET ![22,80], count 20, seconds 10. 22·80 제외를 풀지 말 것. 격상 없음. MITRE T1046.
- c2_beacon 1000005. attacker 172.28.0.100에서 victim-web 172.28.0.10:8443/tcp로 가며 30초 내 5회 연결 시 경보 1회(공격자 발생 트래픽 구조 유지). 격상 없음. MITRE 가안 T1071.001, 기본 심각도 SEV2. 실습망 밖으로 나가는 통신을 전제로 쓰지 말 것.
- ssrf 1000006. HTTP 기반 victim-web:80 GET /fetch?url=<내부 주소>. 백엔드가 200이면 SEV1로 격상, 403은 경보만 내고 격상하지 않음(접속 거절). 기본 SEV3. MITRE 가안 T1190. 대상은 실습망 내부 주소만.
카테고리 키 철자는 정확히 c2_beacon, ssrf 입니다. SID 대역 1000001–1000999.

저장소에 HOME_NET 을 덮어쓰는 설정 파일은 없습니다. 목적지·방향이 비어 있는 채 $EXTERNAL_NET 만 전제로 단정하지 마세요.
```
